# GateLogicPlay 구현 명세서

기본 게이트(AND, OR, XOR, NAND, NOR, XNOR, NOT)와 입력(스위치, 푸시 버튼), 출력(LED)만 가지고 플립플롭이나 가산기 같은 회로를 직접 조립하는 웹 시뮬레이터입니다. 만든 회로는 **칩**으로 저장해서 다른 회로 안에 다시 넣을 수 있습니다.

> 목업: Design 캔버스의 "메인 편집 화면"과 "칩으로 저장 대화상자"를 기준으로 합니다.

---

## 1. 목표와 범위

### 1.1 MVP에 포함
- 기본 부품 10종: `AND`, `OR`, `XOR`, `NAND`, `NOR`, `XNOR`, `NOT`, `SWITCH`(토글), `PUSH`(누르는 동안만 켜짐), `LED`
- 선택 부품: `CLOCK` (설정에서 켜고 끌 수 있음)
- 캔버스 편집: 부품 배치와 이동, 전선 연결과 삭제, 다중 선택, 실행 취소와 다시 실행
- 이벤트 기반 시뮬레이션: 게이트마다 1틱 지연, 피드백 루프 지원, 진동 감지
- 시뮬레이션 제어: 실행, 일시정지, 한 틱 진행, 속도(1~60Hz)
- 칩 저장과 불러오기, 중첩, 수정 내용 전파
- 파형 패널: 선택한 부품을 보는 모드와 선택 범위를 보는 모드
- 진리표 자동 생성
- 저장: localStorage, JSON 내보내기와 가져오기

### 1.2 이후 단계
- 챌린지 모드(목표 진리표와 자동 채점)
- 다중 비트 버스
- 계정과 공유 링크

## 4. 데이터 모델

### 4.1 핵심 타입

```ts
type Bit = 0 | 1;

type PrimitiveKind = 'AND' | 'OR' | 'XOR' | 'NAND' | 'NOR' | 'XNOR' | 'NOT' | 'SWITCH' | 'PUSH' | 'LED' | 'CLOCK';

type PartKind =
  | { type: 'primitive'; kind: PrimitiveKind }
  | { type: 'chip'; chipId: string };

interface Part {
  id: string;              // 회로 안에서 고유
  kind: PartKind;
  x: number; y: number;    // 격자 좌표 (20px 단위)
  rotation?: 0 | 90 | 180 | 270;
  label?: string;          // SWITCH/PUSH/LED는 핀 이름으로 사용
  props?: { hz?: number }; // CLOCK
}

interface PinRef { partId: string; pin: string }   // pin 예: 'a', 'b', 'y', 'q'

interface Wire {
  id: string;
  from: PinRef;            // 출력 핀
  to: PinRef;              // 입력 핀 (입력 핀 하나에는 전선 하나만 연결)
  points?: { x: number; y: number }[]; // 사용자가 꺾은 경로
}

interface Circuit {
  parts: Part[];
  wires: Wire[];
}
```

### 4.2 칩 정의

```ts
interface ChipDef {
  id: string;              // uuid
  name: string;            // "SR 래치"
  color: string;           // 팔레트 스와치 중 하나
  inputs:  { name: string; partId: string }[];  // 순서 = 핀 순서
  outputs: { name: string; partId: string }[];
  circuit: Circuit;
  createdAt: string;
  updatedAt: string;
  revision: number;
}
```

- 칩의 입력 핀은 내부 회로의 `SWITCH`나 `PUSH` 부품이 되고, 출력 핀은 `LED` 부품이 됩니다. 칩 안에 있을 때 이 부품들은 사용자 입력이 아니라 외부 신호로 동작합니다.
- 칩 블록의 높이는 `max(입력 수, 출력 수) × 핀 간격`으로 정하고, 핀 이름은 블록 안쪽에 표시합니다.

### 4.3 저장 파일 형식

```json
{
  "format": "logiclab",
  "version": 1,
  "library": { "<chipId>": { "...ChipDef" } },
  "workspace": { "parts": [], "wires": [] },
  "openChipId": null
}
```

- 파일 하나를 내보낼 때는 그 칩이 **의존하는 모든 칩**을 함께 넣습니다.
- 가져올 때 같은 `id`의 칩이 이미 있으면 덮어쓰기, 복사본으로 저장, 건너뛰기 중에서 고르게 합니다.
- `version`이 바뀌면 `migrate.ts`에서 단계별로 변환합니다.

## 5. 시뮬레이션 엔진

### 5.1 컴파일 (평탄화)
1. 최상위 회로부터 칩을 재귀적으로 펼쳐서 기본 게이트로만 이루어진 넷리스트를 만듭니다.
2. 부품 id는 경로로 만듭니다. 예: `dff1/latch/or2`. 이 경로로 UI 부품과 엔진 노드를 서로 찾습니다.
3. 결과는 `Net[]`(신호선)과 `Node[]`(게이트)입니다. 각 Net에는 연결된 노드 목록이 있습니다.
4. 칩 라이브러리에 순환 참조가 있으면 컴파일 단계에서 막습니다. 예를 들어 칩 A 안에 A가 들어가는 경우입니다(4.4절 참고).

### 5.2 실행 모델
- **이벤트 기반, 단위 지연**: 모든 게이트는 입력이 바뀌면 **1틱 뒤**에 새 출력을 냅니다.
- 한 틱에서 하는 일은 다음과 같습니다.
  1. 이번 틱에 바뀐 Net을 읽어서 영향을 받는 노드를 모읍니다.
  2. 각 노드를 평가해서 출력이 달라졌으면 다음 틱 큐에 넣습니다.
  3. 다음 틱 큐를 적용하고 틱 카운터를 올립니다.
- 사용자 입력(스위치, 푸시 버튼)과 클럭은 해당 틱의 시작에 Net 값으로 바로 반영합니다.
- 화면 갱신은 `requestAnimationFrame` 안에서 `속도(Hz) / 60`만큼 틱을 돌린 뒤 한 번만 합니다.

```ts
interface Engine {
  load(netlist: Netlist): void;
  setInput(partPath: string, v: Bit): void;
  tick(n?: number): TickResult;
  read(netId: string): Bit;
  reset(): void;
}
interface TickResult { tick: number; changed: string[]; oscillating: string[] }
```

### 5.3 피드백과 안정성
- 초기값은 모든 Net을 0으로 둡니다. SR 래치처럼 처음 상태가 정해지지 않는 회로도 결정적으로 시작하게 하려는 것입니다.
- **안정 판정**: 입력이 바뀐 뒤 `2 × 노드 수` 틱 안에 변화가 멈추면 안정으로 봅니다.
- **진동 감지**: 같은 Net이 최근 32틱 동안 16번 넘게 바뀌면 `oscillating`으로 표시합니다. 이 경우 캔버스에 경고 배지를 띄우고 해당 전선을 깜빡이게 합니다. NOT 게이트 루프를 일부러 만들면 클럭으로 쓸 수 있으므로 시뮬레이션을 멈추지는 않습니다.
- 캔버스에는 상태 배지를 띄웁니다: "피드백 루프 감지됨 · 안정" 또는 "진동 중".
- **보충 (구현 시 확정)**: 32틱 중 16회 초과 규칙만으로는 NOT 3개 루프(주기 6틱, 32틱에 약 11회 변화)를 잡을 수 없습니다. 그래서 피드백 루프(강연결요소)마다 바깥에서 들어오는 신호가 멈춘 뒤 `2 × 루프 노드 수 + 2`틱이 지나도 루프 안에서 변화가 계속되면 진동으로 판정하는 조건을 함께 씁니다. 클럭처럼 바깥 신호가 계속 바뀌어 생기는 변화는 진동으로 보지 않습니다.
- 모든 Net이 0인 대칭 상태에서 시작하면 단위 지연 모델에서는 SR 래치가 셋/리셋 전까지 진동하고, NOT 3개 루프는 주기 2로 돕니다. 주기 6틱은 편집기에서처럼 안정된 NOT 사슬을 마지막 전선으로 닫았을 때의 값입니다.

### 5.4 게이트 평가

| 부품 | 입력 | 출력 |
|---|---|---|
| AND | a, b | y = a & b |
| OR | a, b | y = a \| b |
| XOR | a, b | y = a ^ b |
| NAND | a, b | y = 1 − (a & b) |
| NOR | a, b | y = 1 − (a \| b) |
| XNOR | a, b | y = 1 − (a ^ b) |
| NOT | a | y = 1 − a |
| SWITCH | (사용자) | y = 저장된 상태 |
| PUSH | (사용자) | y = 누르고 있으면 1 |
| CLOCK | (시간) | 반주기마다 반전 |
| LED | a | (표시만) |
| SEG8 (추가) | a, b, c, d, e, f, g, dp | (표시만) — 8세그먼트 표시기 |
| VCC (추가) | (없음) | y = 1 (첫 틱부터. 초기 Net 0 규칙에 따라 틱 0에는 0) |
| GND (추가) | (없음) | y = 0 |

입력이 연결되지 않은 핀은 0으로 봅니다. 이 핀은 인스펙터에서 경고로 표시합니다.

- **입력 수 (추가)**: AND, OR, XOR, NAND, NOR, XNOR는 입력을 2~8개(`props.inputs`, 없으면 2) 고를 수 있습니다. 입력 핀은 `a, b, c, …`. AND는 모두 1, OR는 하나라도 1, XOR는 1이 홀수 개일 때 1이고 NAND/NOR/XNOR는 그 반대입니다. 입력이 몇 개든 게이트 하나이므로 지연은 1틱입니다. 입력이 3개 이상이면 입력마다 2칸씩 높아집니다. 입력 수를 줄여 없어진 핀의 전선은 지웁니다.

## 6. 화면 구성

### 6.1 헤더
- 로고, 이동 경로(`내 칩 / SR 래치`), 저장 상태 배지
- 시뮬레이션 제어: 실행/일시정지, 한 틱 진행, 속도 슬라이더(Hz 표시)
- `진리표`, `칩으로 저장` 버튼
- **메뉴바 (추가)**: 로고 옆에 `파일`(가져오기, 내보내기, 예제, 공유 링크), `편집`(실행 취소, 다시 실행, 선택 회전, 선택 삭제, 선택 범위를 칩으로, 칩으로 저장, 칩 편집/챌린지 닫기), `시뮬레이션`(실행/일시정지, 한 틱 진행, 초기화), `도구`(진리표, 챌린지, 설정) 메뉴를 둡니다. 버튼으로는 시뮬레이션 제어, 실행 취소/다시 실행, `가져오기`, `내보내기`, `칩으로 저장`(챌린지 중 숨김), `닫기`(칩 편집·챌린지 중)만 남깁니다. 메뉴는 클릭이나 Enter·↓로 열고, 열린 동안 다른 메뉴 이름에 마우스를 올리거나 ←→로 옮기며, ↑↓로 항목 이동, Esc·바깥 클릭으로 닫습니다. 항목 오른쪽에 단축키를 적습니다. 쓸 수 없는 항목은 비활성으로 보여 줍니다.

### 6.2 왼쪽 팔레트
- 검색 입력
- **기본 게이트**: 2열 격자입니다. 각 버튼 안에 표준 게이트 기호(SVG)와 이름을 넣습니다.
  - AND: D자 모양, OR: 방패 모양, XOR: OR 앞에 곡선 하나 추가, NAND/NOR/XNOR: AND/OR/XOR 끝에 작은 원(버블), NOT: 삼각형과 작은 원
- **입력 · 출력**
  - 스위치: 온오프 토글 스위치 아이콘, 설명은 "누르면 켜짐 유지"
  - 푸시 버튼: 받침 위에 볼록한 캡이 있는 아이콘, 설명은 "누르는 동안만 켜짐"
  - LED: 빛나는 원
  - 8세그먼트 (추가): 세그먼트 a~g와 점(dp)을 각각 1비트 입력 핀으로 받아 켜진 세그먼트를 보여 줍니다. 핀은 1칸 간격, 크기 5×9칸. 칩 핀은 되지 않습니다(표시 전용).
  - 클럭: 사각파 아이콘(선택 사항이라 점선 테두리)
- **2열 배치 (추가)**: 입력·출력, 버스, 내 칩도 기본 게이트처럼 한 줄에 2개씩 놓습니다.
- **내 칩**: 이름과 `입력→출력` 핀 수를 보여줍니다. 지금 열린 칩은 강조합니다.
  - **설정 메뉴 (추가)**: 칩마다 오른쪽 아래 ⚙ 버튼 하나를 두고, 누르면 팝업 메뉴로 `편집`, `분류 바꾸기`, `삭제`가 나옵니다. 바깥 클릭이나 Esc로 닫히고 ↑↓로 항목을 옮깁니다. 편집 중인 칩이나 챌린지 중에는 `편집`이 비활성입니다.
  - **분류 (추가)**: 칩마다 분류(`category`, 선택)를 둘 수 있습니다. 칩으로 저장 창의 "분류" 칸, ⚙ 메뉴의 "분류 바꾸기", 또는 칩을 분류 머리글로 끌어다 놓아 정합니다. 분류가 하나라도 있으면 분류별로 묶어 보여 주고(가나다순, "분류 없음"은 맨 뒤), 머리글로 접고 펼 수 있으며 접은 상태는 브라우저에 기억합니다. 머리글의 ✎로 분류 이름을 바꾸면 그 분류의 칩이 모두 바뀝니다. 검색은 분류 이름도 찾습니다.
- (가져오기·내보내기는 헤더로 옮김)
- 부품은 끌어서 놓거나 클릭한 뒤 캔버스를 클릭해서 배치합니다.

### 6.3 캔버스
- 20px 점 격자, 이동(빈 곳 드래그, 스페이스 + 드래그, 가운데 버튼), 확대와 축소(25~400%), 전체 보기 버튼(모든 부품이 보이게 맞춤, 100%보다 크게는 확대하지 않음)
- 전선: 출력 핀에서 끌어서 입력 핀에 놓습니다. 값이 1이면 강조색, 0이면 회색입니다. 갈라지는 지점에는 점을 찍습니다.
  - 경로는 부품을 피해 자동으로 찾습니다. 전선 하나를 선택하면 구간마다 손잡이가 보이고, 끌면 그 구간이 직각 방향으로 옮겨져 꺾은 점이 `points`에 저장됩니다(실행 취소 가능). 꺾은 전선은 부품이 움직여도 모양을 유지하고 자동 경로 전선이 피해 갑니다. 인스펙터의 "자동 경로로 되돌리기"로 되돌립니다.
- 부품 위에서 스위치나 푸시 버튼을 바로 조작할 수 있습니다. 푸시 버튼은 `pointerdown`에서 1, `pointerup`이나 `pointerleave`에서 0이 됩니다.
- 선택: 클릭하면 하나, Shift+클릭이면 추가, 빈 곳을 **Shift+드래그**하면 **범위 선택**(점선 박스와 "범위 선택 · 부품 N개" 라벨, Ctrl/⌘도 누르면 지금 선택에 추가). 빈 곳을 끌지 않고 클릭하면 선택 해제
  - **변경**: 처음에는 빈 곳 드래그가 범위 선택이었으나, 부품을 잘못 끌어 화면 밖으로 보내는 일이 잦아 빈 곳 드래그를 화면 이동으로 바꿨습니다.
- 칩을 더블클릭하면 내부로 들어가고, 이동 경로가 한 단계 깊어집니다. 칩 내부에 있을 때는 그 칩의 신호가 실제 값으로 표시됩니다(읽기 전용으로 보기와 편집 모드 중 선택).
- 하단 상태바: 틱 수, 게이트 수와 전선 수, 0/1 범례, 확대 비율

### 6.4 오른쪽 인스펙터
- **선택한 부품**: 종류, 현재 입력값, 출력값, 지연
- **핀 순서**: 이 회로를 칩으로 만들 때의 입력과 출력 핀(끌어서 순서 변경)
- **진리표(자동)**: 7장 참고
- **사용 중인 곳**: 이 칩을 포함하는 다른 칩 목록

### 6.5 파형 패널 (하단)
목업의 "파형" 영역입니다. 접고 펼 수 있습니다.

- **모드 전환**: `선택한 부품` 또는 `선택 범위`
  - 선택한 부품: 그 부품의 입력 핀마다 하나, 출력 핀마다 하나씩 채널을 만듭니다. 피드백으로 돌아오는 입력은 따로 표시합니다.
  - 선택 범위: 범위 **경계를 넘는 전선**만 채널로 만듭니다(8장 참고). 범위 안쪽 전선은 보여주지 않습니다.
  - 아무것도 선택하지 않으면 회로의 모든 SWITCH, PUSH, LED를 보여줍니다.
- 채널 한 줄은 `종류 배지 | 이름 | 파형 | 현재값`으로 구성합니다. 입력은 파랑(`--sig-in`), 출력은 강조색(`--sig-out`), 피드백은 보라(`--sig-fb`)입니다.
- 위쪽 시간 눈금은 `t−N … 지금`입니다. 기본 창은 최근 20틱이고, 휠로 늘리고 줄일 수 있습니다(최대 512틱).
- 파형 위에 마우스를 올리면 세로 커서와 그 시점의 모든 채널 값을 보여줍니다.
- 일시정지 상태에서는 파형을 드래그해서 과거로 이동할 수 있습니다.
- `기록 지우기`를 누르면 링 버퍼를 비웁니다.

**기록 방식**
```ts
interface Recorder {
  watch(netIds: string[]): void;   // 선택이 바뀔 때마다 호출
  push(tick: number, values: Map<string, Bit>): void;
  window(netId: string, from: number, to: number): Bit[];
}
```
- Net마다 크기 512의 `Uint8Array` 링 버퍼를 둡니다.
- 실행 중에는 **모든 최상위 Net**을 기록합니다. 그래야 선택을 바꿔도 과거 파형을 바로 볼 수 있습니다. 칩 내부 Net은 그 칩을 열었을 때만 기록합니다.
- 렌더링: 값이 바뀌는 지점만 이어서 `M/H/V` 명령으로 SVG path를 만듭니다. 화면 폭에 맞게 `preserveAspectRatio="none"`과 `vector-effect="non-scaling-stroke"`를 씁니다.

## 7. 진리표

- **조합 회로**(피드백 없음): 입력 `2^n` 조합을 모두 넣고 안정될 때까지 돌린 뒤 출력을 기록합니다. `n ≤ 8`까지만 자동으로 생성하고, 그 이상은 버튼을 눌러서 만듭니다.
- **순차 회로**(피드백 있음): 같은 입력에 대해 이전 상태 Q=0, Q=1 두 경우를 각각 시험합니다. 결과에 따라 칸을 이렇게 채웁니다.
  - 두 경우 출력이 같으면 그 값
  - 이전 상태를 그대로 따르면 `이전 유지`
  - 진동하거나 Q와 Q̄가 같아지면 `금지 상태`
- 현재 입력 조합에 해당하는 행을 강조합니다.
- **보충 (구현 시 확정)**: 이전 상태는 초기 상태(모든 Net 0)에서 입력 조합을 최대 3번 차례로 넣어 도달하는 상태 중 안정되고 금지 상태가 아닌 것에서 고릅니다. 플립플롭처럼 모든 Net이 0인 상태에서는 안정되지 않는 회로도 "클럭 0 → 1"처럼 입력을 이어서 넣으면 정상 상태에 닿기 때문입니다. 이전 상태에 따라 결과가 갈리는데 이전 출력을 그대로 따르지도 않으면 `?`로 표시합니다.

## 8. 범위 선택 → 경계 신호 계산

선택된 부품 집합을 `S`라고 하면:

```ts
function boundary(circuit: Circuit, S: Set<string>) {
  const inputs = [], outputs = [];
  for (const w of circuit.wires) {
    const fromIn = S.has(w.from.partId), toIn = S.has(w.to.partId);
    if (!fromIn && toIn) inputs.push(w);   // 밖 → 안 : 입력
    if (fromIn && !toIn) outputs.push(w);  // 안 → 밖 : 출력
  }
  // 같은 출처(from)에서 갈라져 들어오는 입력은 하나로 합칩니다
  return { inputs: dedupeBySource(inputs), outputs: dedupeBySource(outputs) };
}
```

- 채널 이름은 바깥쪽 부품의 라벨을 씁니다(예: R, S, Q, Q̄). 라벨이 없으면 `부품종류#번호.핀`으로 짓습니다.
- 같은 결과를 **"선택 범위를 칩으로 만들기"**에도 그대로 씁니다. 경계 입력은 칩의 입력 핀이 되고, 경계 출력은 출력 핀이 되며, 원래 자리에는 새 칩 블록이 들어갑니다.

## 9. 칩 저장 흐름

1. `칩으로 저장`을 누르면 대화상자가 열립니다.
2. 입력 항목: 이름(필수, 중복 불가), 색상(5개 스와치), 핀 이름과 순서
3. 미리보기: 핀 이름이 블록 안쪽에 표시된 칩 블록
4. 요약: 내부 부품 수, 피드백 루프 여부, 진리표 검사 결과
5. 이미 다른 칩에서 쓰이고 있는 칩이면 "사용하는 칩에도 변경 사항 반영" 체크박스를 보여줍니다(기본값은 켜짐).
   - 핀이 **삭제되면** 연결이 끊기는 전선 수를 미리 알려줍니다.
   - **변경**: 핀은 내부 부품(SWITCH/PUSH/LED)으로 추적하므로, 이름만 바뀐 핀은 쓰는 곳의 전선도 새 이름으로 바꿔 연결을 유지합니다.
   - 체크를 끄면 `이름 (2)`라는 새 칩으로 저장합니다.
6. 저장이 끝나면 팔레트의 "내 칩"에 추가하고 `revision`을 올립니다.

### 9.1 의존성 관리
- `library.ts`에서 칩 간 의존성 그래프를 관리합니다.
- 칩 A를 편집하는 동안에는 팔레트에서 A, 그리고 A를 포함하는 칩들을 비활성화합니다(순환 방지).
- 칩을 삭제하려면 먼저 그 칩을 쓰는 곳이 없어야 합니다. 쓰는 곳이 있으면 목록을 보여주고 삭제를 막습니다.

## 9.1 그룹·메모·초기화 (추가)

- **그룹**: 부품을 선택하고 `편집 → 선택을 그룹으로 묶기`(Ctrl+Shift+G) 또는 인스펙터의 `그룹으로 묶기`로 이름을 붙여 묶습니다(비우면 "그룹 N"). 캔버스에는 묶은 부품을 감싸는 점선 사각형과 왼쪽 위 이름표를 그립니다. 이름표를 누르면 그룹 전체가 선택되고(끌면 함께 이동, 두 번 누르면 이름 바꾸기), 인스펙터에서 이름 바꾸기·`그룹 풀기`를 합니다. 그룹 전체가 선택되어 있으면 파형은 부품이 하나여도 `선택 범위` 모드(8장 경계 신호)로, 요약에 `그룹 "이름" 경계`를 적습니다. 부품을 지우면 그룹에서 빠지고, 빈 그룹은 사라집니다. 그룹은 겹칠 수 있습니다.
- **캔버스 도구 (추가)**: 팔레트 맨 위에 `✋ 이동`, `⬚ 선택`, `📝 메모` 버튼을 둡니다. 이동(기본)이면 바닥을 끌어 화면 이동(Shift+드래그는 범위 선택), 선택이면 바닥을 끌어 범위 선택(Space+드래그·가운데 버튼은 화면 이동)입니다. 단축키 H/V. 상태 표시줄 안내도 도구에 맞게 바뀝니다.
- **메모**: 팔레트의 `📝 메모`를 누른 뒤 캔버스를 클릭한 칸에 놓거나(Esc로 취소), `편집 → 메모 추가`로 화면 가운데에 놓고 바로 씁니다. 두 번 누르면 다시 고치고(Esc·Ctrl+Enter·바깥 클릭으로 마침), 끌어서 옮기고, 선택해 Delete로 지웁니다. 범위 선택에도 들어가며 부품과 함께 옮길 수 있습니다. 쓰는 동안에는 캔버스 단축키가 동작하지 않습니다.
- **초기화**: `파일 → 작업 공간 비우기`(칩 편집 중이면 `칩 회로 비우기`)는 확인 후 지금 회로의 부품·전선·그룹·메모를 지우며 실행 취소할 수 있습니다. `파일 → 모두 초기화 (내 칩까지)`는 작업 공간과 내 칩을 모두 지우고 실행 취소 기록도 비웁니다(되돌릴 수 없음, 챌린지 기록은 남김). 챌린지 중에는 둘 다 쓸 수 없습니다. 시뮬레이션 초기화(모든 Net 0)는 그대로 `시뮬레이션 → 초기화`와 ↺ 버튼입니다.

## 10.1 운영자 예제 (추가)

- 챌린지 중에는 `예제` 버튼을 숨깁니다.

## 13. 구현 단계와 완료 기준

### 1단계: 편집기 뼈대
- 부품 배치, 이동, 삭제, 전선 연결, 실행 취소
- **완료 기준**: 스위치 → AND → LED를 연결하고 새로고침해도 회로가 남아 있음

### 2단계: 엔진
- 컴파일, tick, 실행 제어, 전선 색 표시
- **완료 기준**: OR와 NOT으로 만든 SR 래치가 R과 S 버튼으로 셋과 리셋되고, 버튼을 놓아도 값이 유지됨. NOT 3개 루프는 "진동 중"으로 표시됨

### 3단계: 파형과 인스펙터
- Recorder, 파형 패널의 두 모드, 범위 선택, 진리표
- **완료 기준**: SR 래치의 OR 하나를 선택하면 입력 2개와 출력 1개 파형이 보임. 래치 전체를 범위로 선택하면 R, S, Q, Q̄ 네 채널만 보임

### 4단계: 칩
- 칩으로 저장, 범위를 칩으로 만들기, 중첩, 내부 들어가기, 변경 전파, 내보내기와 가져오기
- **완료 기준**: SR 래치 → D 플립플롭 → 4비트 레지스터 순서로 중첩해도 동작함. 래치를 수정하면 레지스터에 반영됨

### 5단계: 다듬기
- 클럭, 단축키, 진동 경고, 성능(게이트 5천 개에서 60fps)
- **보충 (구현 시 확정)**: 성능은 배포 빌드(`vite preview`)에서 잽니다. 기준 회로는 NOT/XOR 사슬 100줄 × 50개(게이트 5천 개, 연결은 대부분 이웃끼리)이고, 클럭으로 계속 구동하며 60Hz로 실행합니다(`tests/e2e/perf.spec.ts`). 화면 밖 부품·전선은 그리지 않고, 전선 값은 React를 거치지 않고 바뀐 것만 DOM에 씁니다.

### 6단계: 챌린지 모드 (1.2절 이후 단계에서 추가)
- 헤더 `챌린지` 버튼 → 챌린지 목록. 챌린지마다 제목, 설명, 쓸 수 있는 부품, 목표 진리표, 모범 답안 게이트 수가 있습니다.
- 챌린지를 시작하면 작업 공간을 맡겨 두고(칩 편집과 같은 방식) 이름 붙은 입력 스위치와 출력 LED가 놓인 빈 회로가 열립니다. 이동 경로는 `챌린지 / 제목`.
- 쓸 수 없는 부품은 팔레트에서 비활성화합니다. 칩은 펼친 내부 게이트가 모두 허용된 경우에만 쓸 수 있고, 클럭은 쓸 수 없습니다.
- **자동 채점**: 회로 구조가 바뀔 때마다 7장의 진리표 엔진으로 목표 진리표와 비교합니다. 목표 칸은 `0`/`1`, `이전 유지`, `상관없음`(금지 상태 허용) 중 하나입니다. 행마다 맞음/틀림을 표시하고, 모두 맞으면 "통과"와 게이트 수(펼친 기준)를 보여 줍니다.
- 입력이나 출력 이름이 빠졌거나 챌린지에 없는 입력을 추가하면 채점하지 않고 이유를 알려 줍니다.
- 진행 상황(챌린지별 회로, 통과 여부, 최소 게이트 수)은 localStorage `logiclab:v1:challenges`에 저장합니다.
- **완료 기준**: NAND만으로 XOR 챌린지를 풀면 "통과"가 표시되고 NAND 외 게이트는 팔레트에서 비활성화됨. 틀린 회로는 틀린 행이 표시됨. NOR로 만든 SR 래치 챌린지는 이전 유지·금지 상태 행까지 채점됨. 진행 상황은 새로고침해도 남음

### 7단계: 공유 링크 (계정 없이)
- 헤더 `공유` 버튼 → 지금 회로(작업 공간 또는 편집 중인 칩)와 쓰는 칩 전체를 4.3절 파일 형식으로 묶어 압축(deflate)한 뒤 base64url로 URL 해시(`#share=`)에 넣은 링크를 만듭니다. 서버가 필요 없습니다.
- 링크로 열면 4.3절 가져오기 대화상자(검증·충돌 선택)를 그대로 거친 뒤 반영하고, 해시는 지웁니다. 잘못된 링크는 오류로 알립니다.
- 링크가 8,000자를 넘으면 메신저에서 잘릴 수 있다고 알리고 JSON 내보내기를 권합니다.
- 계정은 서버가 필요해 이번 범위에서 제외합니다.
- **완료 기준**: SR 래치 칩을 쓰는 회로의 공유 링크를 새 창에서 열면 가져오기 대화상자가 뜨고, 확인하면 같은 회로와 칩이 열려 셋·리셋이 동작함. 망가진 링크는 거부됨

### 8단계: 다중 비트 버스 (1.2절 이후 단계에서 추가)
- **비트 수**: 부품마다 `props.bits`(1~16, 없으면 1)를 둡니다. 인스펙터에서 바꿉니다.
  - 게이트(AND·OR·XOR·NAND·NOR·XNOR·NOT): 비트마다 따로 계산(비트 연산). 입력·출력 핀 모두 N비트.
  - 스위치: N비트 입력. 클릭하면 값이 1씩 늘고(2^N에서 0으로), 인스펙터에서 값을 직접 넣을 수 있습니다. 푸시 버튼과 클럭은 1비트만.
  - LED: N비트이면 숫자 표시(10진수, 인스펙터에 2진수).
  - 새 부품 **나누기**(`SPLIT`, 입력 `a`[N] → 출력 `y0`…`y(N-1)` 각 1비트)와 **묶기**(`MERGE`, `a0`…`a(N-1)` → `y`[N]). 기본 4비트. 0번 비트가 맨 위.
- **전선**: 양쪽 핀의 비트 수가 같을 때만 연결합니다. 2비트 이상 전선(버스)은 굵게 그리고, 비트 중 하나라도 1이면 강조색입니다. 비트 수를 바꿔 맞지 않게 된 전선은 지웁니다.
- **칩 핀**: 내부 스위치·LED의 비트 수가 그대로 칩 핀의 비트 수가 됩니다. 범위를 칩으로 만들 때도 경계 신호의 비트 수를 유지합니다.
- **엔진**: 컴파일할 때 N비트 핀을 1비트 Net N개로 펼칩니다. 엔진(1틱 지연, 이벤트 기반)은 바뀌지 않습니다. 0번 비트의 id는 기존과 같고(`and1`), k번 비트는 `and1[k]`, 핀 키는 `and1.y[k]`입니다. 나누기·묶기는 지연 없는 배선(별칭)입니다.
- **파형**: N비트 채널은 값이 바뀌는 지점마다 교차 표시가 있는 버스 모양으로 그리고 구간마다 값(10진수)을 적습니다.
- **진리표**: N비트 입력·출력은 비트마다 열을 만듭니다(`A[0]`, `A[1]`…). 입력 비트 합이 8을 넘으면 자동 생성하지 않습니다.
- **저장 형식 version 2**: `PrimitiveKind`에 `SPLIT`, `MERGE` 추가, `props.bits` 추가. version 1 파일은 그대로 읽을 수 있도록 `migrate.ts`에 1 → 2 단계를 둡니다(구조 변화 없음).
- **저장 형식 version 3 (추가)**: 게이트 입력 수 `props.inputs`(2~8)와 칩 분류 `ChipDef.category`를 추가했습니다. 둘 다 없으면 기존과 같으므로 2 → 3 단계는 버전만 올립니다.
- **저장 형식 version 4 (추가)**: `PrimitiveKind`에 `SEG8`(8세그먼트 표시기)을 추가했습니다. 3 → 4 단계는 버전만 올립니다.
- **저장 형식 version 6 (추가)**: `Circuit`에 선택 필드 `groups`(`{id, name, parts[]}`)와 `notes`(`{id, x, y, text}`)를 추가했습니다. 둘 다 시뮬레이션에는 쓰지 않습니다. 5 → 6 단계는 버전만 올립니다.
- **저장 형식 version 5 (추가)**: `PrimitiveKind`에 상수 `VCC`, `GND`를 추가했습니다(비트 수 선택 가능, 챌린지에서는 쓸 수 없음). 4 → 5 단계는 버전만 올립니다.
- **연결 실패 안내 (추가)**: 전선을 핀에 놓았는데 비트 수가 다르거나 출력끼리·입력끼리라서 잇지 못하면, 상태 표시줄에 이유를 4초 동안 보여 줍니다.
- **완료 기준**: 4비트 스위치 두 개를 4비트 칩(4비트 가산기를 버스 핀으로 감싼 것)에 버스로 연결하면 합이 숫자 LED에 표시됨. 나누기·묶기를 거쳐도 값이 같음. 비트 수가 다른 핀은 연결되지 않음. version 1 파일을 가져올 수 있음

## 14. 테스트 케이스

| 회로 | 검증할 내용 |
|---|---|
| 반가산기 (XOR + AND) | 4개 조합 진리표: S = A⊕B, C = A·B |
| 전가산기 (반가산기 칩 2개 + OR) | 8개 조합 진리표 |
| SR 래치 (OR 2 + NOT 2) | 셋, 리셋, 유지, 금지 상태 판정 |
| D 래치 (SR 래치 + AND 2 + NOT) | CLK=1일 때 Q가 D를 따르고, CLK=0이면 유지 |
| D 플립플롭 (D 래치 2개, 마스터-슬레이브) | 클럭 상승 에지에서만 값을 저장 |
| NOT 3개 루프 | 진동 감지, 주기 = 6틱 |
| 4비트 리플 캐리 가산기 | 256개 조합, 칩 중첩 3단계 |
| 순환 칩 참조 | 칩 A 안에 A를 넣으려 하면 막힘 |
| 가져오기 | 잘못된 JSON은 거부, 같은 id 충돌 시 선택 대화상자 표시 |

엔진 테스트는 UI 없이 `compile → setInput → tick → read`만으로 작성합니다.
