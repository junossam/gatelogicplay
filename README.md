# LogicLab

기본 게이트와 스위치·푸시 버튼·LED만으로 래치, 플립플롭, 가산기 같은 회로를 직접 조립해 보는 웹 시뮬레이터입니다. 만든 회로는 **칩**으로 저장해서 다른 회로 안에 다시 넣을 수 있고, 여러 단계로 중첩할 수 있습니다.

- 게이트마다 1틱씩 늦게 반응하는 **이벤트 기반 시뮬레이션** — 피드백 루프(래치)가 실제처럼 동작하고, 진동은 멈추지 않고 표시만 합니다.
- **파형**, **진리표**, **칩 저장·중첩**, **다중 비트 버스**, **챌린지(자동 채점)**, **공유 링크**를 지원합니다.
- 서버 없이 브라우저에서만 동작하며, 작업은 브라우저 저장소(localStorage)에 자동 저장됩니다.

전체 명세는 [`docs/SPEC.md`](docs/SPEC.md)에 있습니다.

## 실행

Node.js 20 이상과 [pnpm](https://pnpm.io/)이 필요합니다.

```bash
pnpm install
```

```bash
pnpm dev
```

터미널에 나오는 주소(보통 `http://localhost:5173`)를 브라우저에서 엽니다.

배포용 빌드는 `pnpm build`로 만들고 `pnpm preview`로 확인합니다. 결과물(`dist/`)은 정적 파일이라 아무 웹 서버에나 올리면 됩니다.

## 조작법

### 부품과 전선
- **배치**: 팔레트에서 부품을 클릭한 뒤 캔버스를 클릭하거나, 캔버스로 끌어다 놓습니다.
- **이동**: 부품 몸체를 끕니다. 20px 격자에 맞춰집니다.
- **전선 연결**: 출력 핀에서 끌어 입력 핀에 놓습니다. 입력 핀에는 전선 하나만, 출력 핀에는 여러 개를 연결할 수 있습니다. 비트 수가 같은 핀끼리만 연결됩니다.
- **전선 꺾기**: 전선 하나를 선택하면 구간마다 네모 손잡이가 보입니다. 끌면 그 구간이 직각 방향으로 옮겨집니다. 인스펙터의 "자동 경로로 되돌리기"로 되돌립니다.
- 전선은 부품을 피해 자동으로 경로를 찾습니다. 갈라지는 지점에는 점(●)이, 연결되지 않고 엇갈리는 곳에는 끊긴 틈이 보입니다. 전선이 꽂힌 핀은 채운 점, 빈 핀은 고리로 표시됩니다.

### 화면과 선택
- **화면 이동**: 빈 곳을 끌거나, 스페이스+드래그, 가운데 버튼 드래그
- **확대·축소**: 마우스 휠 (25~400%)
- **전체 보기**: 캔버스 오른쪽 아래 ⤢ 버튼
- **선택**: 클릭은 하나, Shift+클릭은 추가, 빈 곳을 **Shift+드래그**하면 범위 선택
- **조작**: 스위치는 클릭하면 토글(여러 비트 스위치는 1씩 증가), 푸시 버튼은 캡을 누르고 있는 동안만 1

### 단축키 (캔버스에 포커스가 있을 때)

## 기능

### 부품
- 게이트: AND, OR, XOR, NAND, NOR, XNOR, NOT — 모두 1틱 지연
- 입력: 스위치(누르면 켜짐 유지), 푸시 버튼(누르는 동안만), 클럭(설정에서 켜고 끔, 주파수는 인스펙터에서)
- 출력: LED
- 버스: 나누기(버스 → 비트), 묶기(비트 → 버스)

### 칩
- **칩으로 저장**: 회로를 이름·색과 함께 칩으로 저장합니다. 스위치·푸시 버튼이 입력 핀, LED가 출력 핀이 됩니다. 저장 창에서 핀 이름과 순서, 핀으로 쓸지 여부를 정합니다(전선이 없는 입출력은 기본으로 빠짐).
- **범위를 칩으로**: 부품을 범위로 선택하고 Ctrl+G. 경계를 넘는 신호가 칩 핀이 되고 원래 자리에 칩 블록이 들어갑니다.
- **중첩과 내부 보기**: 칩 안에 칩을 넣을 수 있습니다. 칩을 더블클릭하면 내부를 읽기 전용으로 보며 실제 신호 값을 확인할 수 있습니다.
- **편집과 변경 전파**: 팔레트의 ✎로 칩을 열어 고치고 저장하면, 그 칩을 쓰는 모든 곳에 반영됩니다. 핀 이름만 바꾸면 쓰는 곳의 전선도 새 이름으로 이어지고, 핀을 지우면 그 전선만 끊깁니다(저장 전에 개수를 알려 줍니다).
- 칩 A를 편집하는 동안 A와 A를 포함하는 칩은 넣을 수 없고(순환 방지), 쓰는 곳이 있는 칩은 지울 수 없습니다.

### 다중 비트 버스
- 게이트·스위치·LED·나누기·묶기의 **비트 수**(1~16)를 인스펙터에서 바꿉니다.
- 여러 비트 게이트는 비트마다 따로 계산하고, 여러 비트 스위치는 숫자 값을, 여러 비트 LED는 숫자를 표시합니다.
- 칩 핀은 내부 스위치·LED의 비트 수를 그대로 가집니다. 버스 전선은 굵게, 파형은 값이 적힌 버스 모양으로 보입니다.

### 파형과 진리표
- **파형**: 부품 하나를 고르면 그 부품의 입출력 핀(피드백으로 돌아오는 입력은 보라색), 여러 개를 고르면 범위 경계를 넘는 신호만 보여 줍니다. 휠로 창 크기 조절, 일시정지 중에는 끌어서 과거로 이동, 마우스를 올리면 그 시점 값.
- **진리표**: 조합 회로는 모든 입력 조합, 순차 회로는 이전 상태별로 시험해 "이전 유지"와 "금지 상태"까지 보여 줍니다. 현재 입력 행을 강조합니다.

### 챌린지
헤더의 **챌린지**에서 목표 진리표에 맞는 회로를 만드는 문제 10개(NAND로 XOR 만들기, 전가산기, NOR SR 래치, NAND D 래치 등)를 풉니다. 회로를 고칠 때마다 자동 채점하고, 통과하면 게이트 수를 모범 답안과 비교합니다.

### 저장·공유
- **자동 저장**: 편집 후 1초 뒤 브라우저 저장소에 저장합니다. 칩 편집 중 저장하지 않은 변경은 칩 저장 전까지 저장되지 않습니다(경고 표시).
- **내보내기/가져오기**: 팔레트 아래 버튼. 회로와 쓰는 칩을 JSON 파일 하나로 주고받습니다. 같은 칩이 이미 있으면 덮어쓰기/복사본/건너뛰기 중에서 고릅니다.
- **공유 링크**: 헤더의 **공유**. 회로와 칩을 압축해 URL에 담습니다. 서버나 계정이 필요 없습니다.

## 예제

[`examples/flipflops.logiclab.json`](examples/flipflops.logiclab.json) — SR 래치, D 래치와 SR·D·JK·T 플립플롭(상승 에지) 칩, 바로 눌러 볼 수 있는 데모 작업 공간. 팔레트의 **가져오기**로 불러옵니다.

> 모든 Net은 0에서 시작하므로 래치·플립플롭은 처음에 깜빡이며 "진동 중"으로 표시됩니다. 셋/리셋하거나(JK는 K=1, D는 D=0, T는 CLR을 켜고) 클럭을 한 번 주면 정리됩니다.

## 파일 형식

```json
{
  "format": "logiclab",
  "version": 2,
  "library": { "<칩 id>": { "id": "...", "name": "SR 래치", "inputs": [], "outputs": [], "circuit": {} } },
  "workspace": { "parts": [], "wires": [] },
  "openChipId": null
}
```

가져올 때 [zod](https://zod.dev/) 스키마로 검증하고, 실패하면 어떤 필드가 문제인지 알려 줍니다. 이전 버전 파일은 `src/model/migrate.ts`에서 단계별로 변환해 읽습니다.

## 개발

| 명령 | 내용 |
|---|---|
| `pnpm dev` | 개발 서버 |
| `pnpm test` | 단위 테스트 (Vitest) |
| `pnpm test:e2e` | E2E 테스트 (Playwright). 처음 한 번 `pnpm exec playwright install chromium` 필요 |
| `pnpm typecheck` | 타입 검사 |
| `pnpm lint` | ESLint |
| `pnpm build` | 배포용 빌드 |

E2E는 개발 서버(5179)와 배포 빌드 미리보기(5180)를 함께 띄웁니다. 성능 테스트(게이트 5천 개에서 60fps)는 배포 빌드로, 기능 테스트가 끝난 뒤 따로 실행합니다.

### 구조

```
src/sim/     시뮬레이션 엔진 — 순수 TypeScript, React/DOM 의존 없음
             compile(칩 평탄화·버스 펼치기) → Engine(setInput → tick → read)
src/model/   저장 스키마, 칩 라이브러리, localStorage, 마이그레이션, 챌린지, 공유 링크
src/store/   editorStore(문서·선택·실행 취소), simStore(실행·속도·틱·파형 기록)
src/ui/      Header, Palette, Canvas(경로 찾기 포함), Inspector, Waveform, TruthTable, dialogs, challenges
src/theme/   tokens.css (색은 여기서만 정의)
tests/       fixtures(예제 회로), unit, e2e
```

엔진 테스트는 UI 없이 `compile → setInput → tick → read`만으로 작성합니다. 작업 규칙은 [`CLAUDE.md`](CLAUDE.md)를 참고하세요.
