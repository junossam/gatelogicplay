# GateLogicPlay

기본 게이트와 스위치·푸시 버튼·LED만으로 래치, 플립플롭, 가산기 같은 회로를 직접 조립해 보는 웹 시뮬레이터입니다. 만든 회로는 **칩**으로 저장해서 다른 회로 안에 다시 넣을 수 있고, 여러 단계로 중첩할 수 있습니다.

- 게이트마다 1틱씩 늦게 반응하는 **이벤트 기반 시뮬레이션** — 피드백 루프(래치)가 실제처럼 동작하고, 진동은 멈추지 않고 표시만 합니다.
- **파형**, **진리표**, **칩 저장·중첩**, **다중 비트 버스**, **챌린지(자동 채점)**, **공유 링크**를 지원합니다.
- 서버 없이 브라우저에서만 동작하며, 작업은 브라우저 저장소(localStorage)에 자동 저장됩니다.

전체 명세는 [`docs/SPEC.md`](docs/SPEC.md)에 있습니다.

## 실행

Node.js 20 이상과 [pnpm](https://pnpm.io/)이 필요합니다.

```bash
pnpm install
```

```bash
pnpm dev
```

터미널에 나오는 주소(보통 `http://localhost:5173`)를 브라우저에서 엽니다.

배포용 빌드는 `pnpm build`로 만들고 `pnpm preview`로 확인합니다. 결과물(`dist/`)은 정적 파일이라 아무 웹 서버에나 올리면 됩니다.

## 조작법

### 부품과 전선
- **배치**: 팔레트에서 부품을 클릭한 뒤 캔버스를 클릭하거나, 캔버스로 끌어다 놓습니다.
- **이동**: 부품 몸체를 끕니다. 20px 격자에 맞춰집니다.
- **전선 연결**: 출력 핀에서 끌어 입력 핀에 놓습니다. 입력 핀에는 전선 하나만, 출력 핀에는 여러 개를 연결할 수 있습니다. 비트 수가 같은 핀끼리만 연결되고, 연결할 수 없으면 아래 상태 표시줄에 이유가 나옵니다.
- **전선 꺾기**: 전선 하나를 선택하면 구간마다 네모 손잡이가 보입니다. 끌면 그 구간이 직각 방향으로 옮겨집니다. 인스펙터의 "자동 경로로 되돌리기"로 되돌립니다.
- 전선은 부품을 피해 자동으로 경로를 찾습니다. 갈라지는 지점에는 점(●)이, 연결되지 않고 엇갈리는 곳에는 끊긴 틈이 보입니다. 전선이 꽂힌 핀은 채운 점, 빈 핀은 고리로 표시됩니다.

### 화면과 선택
- **캔버스 도구** (팔레트 맨 위): **✋ 이동**이면 빈 곳을 끌어 화면 이동, **⬚ 선택**이면 빈 곳을 끌어 범위 선택. 단축키 H / V
- **화면 이동**: 이동 도구로 빈 곳을 끌거나, 스페이스+드래그, 가운데 버튼 드래그
- **확대·축소**: 마우스 휠 (25~400%)
- **전체 보기**: 캔버스 오른쪽 아래 ⤢ 버튼
- **선택**: 클릭은 하나, Shift+클릭은 추가, 선택 도구로 빈 곳을 끌거나 **Shift+드래그**하면 범위 선택
- **조작**: 스위치는 클릭하면 토글(여러 비트 스위치는 1씩 증가), 푸시 버튼은 캡을 누르고 있는 동안만 1

### 창 배치
- 왼쪽(부품)·오른쪽(속성) 창은 머리의 **«/»** 버튼으로 숨기고, 숨긴 자리의 버튼으로 다시 펼칩니다.
- 창과 캔버스 사이 경계를 끌면 폭이 바뀝니다(키보드 ←→, Shift는 크게, Home/End는 최소/최대, 두 번 누르면 기본 폭). 숨김·폭은 브라우저에 기억합니다.

## 기능

### 부품
- 상수: VCC(항상 1), GND(항상 0) — 입력·출력 칸에 있고 비트 수를 고를 수 있습니다.
- 게이트: AND, OR, XOR, NAND, NOR, XNOR, NOT — 모두 1틱 지연. NOT 외에는 인스펙터에서 **입력 수(2~8개)**를 고를 수 있습니다(XOR는 1이 홀수 개일 때 1).
- 입력: 스위치(누르면 켜짐 유지), 푸시 버튼(누르는 동안만), 클럭(설정에서 켜고 끔, 주파수는 인스펙터에서)
- 출력: LED, 8세그먼트 표시기(세그먼트 a~g와 점 dp를 핀 하나씩으로 받음)
- 버스: 나누기(버스 → 비트), 묶기(비트 → 버스)

### 칩
- **칩으로 저장**: 회로를 이름·색과 함께 칩으로 저장합니다. 스위치·푸시 버튼이 입력 핀, LED가 출력 핀이 됩니다. 저장 창에서 핀 이름과 순서, 핀으로 쓸지 여부를 정합니다(전선이 없는 입출력은 기본으로 빠짐).
- **범위를 칩으로**: 부품을 범위로 선택하고 Ctrl+G. 경계를 넘는 신호가 칩 핀이 되고 원래 자리에 칩 블록이 들어갑니다.
- **중첩과 내부 보기**: 칩 안에 칩을 넣을 수 있습니다. 칩을 더블클릭하면 내부를 읽기 전용으로 보며 실제 신호 값을 확인할 수 있습니다.
- **칩 내부 펼쳐 보기** (공부용): 회로에 칩이 있으면 오른쪽 인스펙터 맨 위에 **칩 내부: 보지 않기 / 1단계 / 전체** 버튼이 나옵니다. 펼치면 칩 자리에 내부 회로가 풀려 나오고, 칩마다 점선 그룹("칩 이름 (부품 id)")으로 감쌉니다. 신호 값은 실제 값 그대로이고, 바깥 스위치·푸시 버튼은 눌러 볼 수 있습니다. 그룹 이름표를 누르면 그 칩 경계의 파형을 봅니다. 펼쳐 보는 동안은 편집할 수 없습니다("보지 않기"로 돌아가 편집).
- **편집과 변경 전파**: 칩의 ⚙ 메뉴 → 편집으로 칩을 열어 고치고 저장하면, 그 칩을 쓰는 모든 곳에 반영됩니다. 핀 이름만 바꾸면 쓰는 곳의 전선도 새 이름으로 이어지고, 핀을 지우면 그 전선만 끊깁니다(저장 전에 개수를 알려 줍니다).
- 칩 A를 편집하는 동안 A와 A를 포함하는 칩은 넣을 수 없고(순환 방지), 쓰는 곳이 있는 칩은 지울 수 없습니다.
- **칩 내보내기·가져오기**: 칩의 ⚙ 메뉴 → **내보내기**는 그 칩(과 그 칩이 쓰는 칩)만, 팔레트 "내 칩"의 **모두 내보내기**(또는 **파일 → 내 칩 모두 내보내기**)는 내 칩 전부를 JSON 파일로 저장합니다. 작업 공간은 담지 않습니다. 받은 파일은 **칩 가져오기**로 내 칩에 추가합니다(같은 칩이 있으면 덮어쓰기/복사본/건너뛰기). "내 칩" 제목 아래 아이콘 버튼은 📂 칩 가져오기 · 💾 모두 내보내기 · 📦 기본 제공 칩입니다.
- **분류**: 저장 창의 "분류" 칸, 칩의 ⚙ 메뉴 → 분류 바꾸기, 또는 칩을 분류 머리글로 끌어다 놓아 정리합니다. 팔레트는 분류별로 묶어 보여 주고 접고 펼 수 있으며, 머리글의 ✎로 분류 이름을 바꿉니다.

### 그룹·메모
- **그룹**: 부품을 선택하고 **편집 → 선택을 그룹으로 묶기**(Ctrl+Shift+G)나 인스펙터의 **그룹으로 묶기**로 이름을 붙입니다. 점선 사각형과 이름표가 생기고, 이름표를 누르면 그룹 전체가 선택되어 파형에 **그룹 경계를 드나드는 신호**가 보입니다. 이름표를 끌면 함께 움직이고, 두 번 누르면 이름을 바꿉니다.
- **메모**: 팔레트 맨 위 **📝 메모**를 누르고 캔버스를 클릭한 자리에 놓거나, **편집 → 메모 추가**로 화면 가운데에 놓습니다. 두 번 눌러 고치고, 끌어서 옮기고, Delete로 지웁니다.

### 초기화
- **파일 → 작업 공간 비우기**: 지금 회로만 비웁니다(내 칩은 남고, 실행 취소 가능).
- **파일 → 모두 초기화 (내 칩까지)**: 작업 공간과 내 칩을 모두 지웁니다(되돌릴 수 없음).
- ↺ 버튼(**시뮬레이션 → 초기화**)은 회로는 두고 신호만 모두 0으로 되돌립니다.

### 다중 비트 버스
- 게이트·스위치·LED·나누기·묶기의 **비트 수**(1~16)를 인스펙터에서 바꿉니다.
- 여러 비트 게이트는 비트마다 따로 계산하고, 여러 비트 스위치는 숫자 값을, 여러 비트 LED는 숫자를 표시합니다.
- 칩 핀은 내부 스위치·LED의 비트 수를 그대로 가집니다. 버스 전선은 굵게, 파형은 값이 적힌 버스 모양으로 보입니다.

### 파형과 진리표
- **파형**: 부품 하나를 고르면 그 부품의 입출력 핀(피드백으로 돌아오는 입력은 보라색), 여러 개를 고르면 범위 경계를 넘는 신호만 보여 줍니다. 휠로 창 크기 조절, 일시정지 중에는 끌어서 과거로 이동, 마우스를 올리면 그 시점 값.
- **진리표**: 조합 회로는 모든 입력 조합, 순차 회로는 이전 상태별로 시험해 "이전 유지"와 "금지 상태"까지 보여 줍니다. 현재 입력 행을 강조합니다.

### 챌린지
**도구 → 챌린지**에서 목표 진리표에 맞는 회로를 만드는 문제 10개(NAND로 XOR 만들기, 전가산기, NOR SR 래치, NAND D 래치 등)를 풉니다. 회로를 고칠 때마다 자동 채점하고, 통과하면 게이트 수를 모범 답안과 비교합니다.

### 저장·공유
- **자동 저장**: 편집 후 1초 뒤 브라우저 저장소에 저장합니다. 칩 편집 중 저장하지 않은 변경은 칩 저장 전까지 저장되지 않습니다(경고 표시).
- **내보내기/가져오기**: 헤더의 버튼(또는 **파일** 메뉴). 회로와 쓰는 칩을 JSON 파일 하나로 주고받습니다. 같은 칩이 이미 있으면 덮어쓰기/복사본/건너뛰기 중에서 고릅니다.
- **공유 링크**: 헤더의 **공유**(칩으로 저장 옆) 또는 **파일 → 공유 링크**. 회로와 칩을 압축해 URL에 담습니다. 서버나 계정이 필요 없습니다.

## 기본 제공 칩 (운영자가 올려 두는 칩)

팔레트 "내 칩"의 **📦 기본 제공 칩**(또는 **파일 → 기본 제공 칩**)을 누르면 운영자가 미리 올려 둔 칩 묶음을 보고 **내 칩에 추가**할 수 있습니다. 작업 공간은 바뀌지 않습니다.

올리는 방법은 아래 예제와 같고 폴더만 [`chips/`](chips)입니다: 칩을 **내보내기**(⚙ → 내보내기 또는 💾 모두 내보내기)한 JSON을 `chips/<분류>/<이름>.json`으로 넣고 빌드·배포합니다. 파일에 작업 공간이 있어도 칩만 가져옵니다. 지금 들어 있는 것: `chips/기억 소자/플립플롭.json`(래치·플립플롭 6개), `chips/연산/가산기.json`(가산기 3개), `chips/표시/8세그먼트 디코더.json`(2진수 → a~g로 0~F 표시: 4비트 버스 입력 N 칩과 1비트 입력 B0~B3 칩 2개).

## 예제 (운영자가 올려 두는 샘플)

**파일 → 예제**를 누르면 사이트 운영자가 미리 올려 둔 회로를 분류별로 보고 바로 열 수 있습니다. **링크 복사**로 그 예제를 바로 여는 주소(`…/#sample=분류/파일.json`)를 만들어 나눠 줄 수 있습니다.

### 예제 올리는 방법
1. 앱에서 회로를 만들고 팔레트의 **내보내기**로 JSON을 받습니다.
2. 소스의 [`samples/`](samples) 폴더에 넣습니다. **하위 폴더 이름이 분류**, **파일 이름이 제목**이 됩니다. 파일 이름 앞에 `01-`처럼 번호를 붙이면 그 순서로 정렬되고, 번호는 제목에서 빠집니다.
3. 원하면 JSON 맨 위에 제목과 설명을 넣습니다. 이 필드는 가져올 때 무시되므로 파일은 그대로 정상 동작합니다.
   ```json
   { "format": "logiclab", "version": 6, "title": "4비트 가산기", "description": "칩 중첩 예제", "library": {}, "workspace": {} }
   ```
4. `pnpm dev`로 확인합니다. 개발 서버는 새로고침만 하면 바로 반영합니다. 그다음 `pnpm build`로 빌드해 배포합니다. 빌드할 때 모든 예제를 검증해 목록 `samples/index.json`을 만들고, 잘못된 파일이 있으면 빌드가 멈춥니다.

현재 들어 있는 예제:
- `samples/기억 소자/플립플롭 모음.json` — SR 래치, D 래치와 SR·D·JK·T 플립플롭(상승 에지) 칩, 바로 눌러 볼 수 있는 데모 작업 공간
- `samples/연산/4비트 가산기.json` — 반가산기 → 전가산기 → 4비트 버스 가산기 칩 중첩
- `samples/표시/16진수 표시.json` — 4비트 스위치 → 8세그먼트 디코더(버스) 칩 → 8세그먼트

수업용 예제 (칩 없이 기본 게이트로 펼친 회로, 블록마다 점선 그룹과 사용법 메모):

| 파일 | 내용 |
|---|---|
| `기본/NAND로 만든 게이트` | NAND만으로 NOT·AND·OR·XOR |
| `선택/멀티플렉서` | 4:1 MUX(2:1 MUX 3개) · 1:4 DEMUX |
| `선택/디코더·인코더` | 3→8 디코더(2→4 두 개) · 4→2 우선순위 인코더 |
| `연산/비교기` | 1비트 비교기 4개로 4비트 A>B·A=B·A<B |
| `연산/전감산기` | 반감산기 2개 + OR |
| `연산/4비트 ALU` | AND·OR·덧셈·뺄셈(2의 보수) 선택 |
| `기억 소자/레지스터` | 4비트 레지스터 · 시프트 레지스터 |
| `기억 소자/카운터` | 4비트 비동기(리플)·동기 카운터 비교 |
| `표시/0~99 카운터` | BCD 카운터 2개 + BCD→8세그먼트 2개 (클럭) |
| `기타/부호·검사` | 짝수 패리티 생성·검사 · 2진↔그레이 변환 |

이 예제들은 [`tests/fixtures/teaching.ts`](tests/fixtures/teaching.ts)에서 블록을 조립해 펼쳐 만들고, `tests/unit/teaching.test.ts`가 저장된 파일을 엔진으로 진리표·클럭 동작까지 검증합니다. 생성 코드를 고쳤으면 `GEN_SAMPLES=1 pnpm test`로 파일을 다시 만듭니다.

> 모든 Net은 0에서 시작하므로 래치·플립플롭은 처음에 깜빡이며 "진동 중"으로 표시됩니다. 셋/리셋하거나(JK는 K=1, D는 D=0, T는 CLR을 켜고) 클럭을 한 번 주면 정리됩니다.

## 파일 형식

```json
{
  "format": "logiclab",
  "version": 6,
  "library": { "<칩 id>": { "id": "...", "name": "SR 래치", "inputs": [], "outputs": [], "circuit": {} } },
  "workspace": { "parts": [], "wires": [] },
  "openChipId": null
}
```

`format` 값 `"logiclab"`과 브라우저 저장 키 `logiclab:v1:*`는 이전 이름(LogicLab) 때 정한 내부 식별자로, 기존 작업·파일과 호환되도록 그대로 둡니다.

가져올 때 [zod](https://zod.dev/) 스키마로 검증하고, 실패하면 어떤 필드가 문제인지 알려 줍니다. 이전 버전 파일은 `src/model/migrate.ts`에서 단계별로 변환해 읽습니다.

## 배포

`pnpm build` 결과물(`dist/`: `index.html`, `assets/`, `samples/`, `chips/`)은 상대 경로(`base: './'`)로 만들어져 어느 하위 폴더에 올려도 동작합니다. 현재 <https://junossam.github.io/gatelogicplay/> 에 `dist/` 내용만 올려 운영합니다.

## 개발

| 명령 | 내용 |
|---|---|
| `pnpm dev` | 개발 서버 |
| `pnpm test` | 단위 테스트 (Vitest) |
| `pnpm test:e2e` | E2E 테스트 (Playwright). 처음 한 번 `pnpm exec playwright install chromium` 필요 |
| `pnpm typecheck` | 타입 검사 |
| `pnpm lint` | ESLint |
| `pnpm build` | 배포용 빌드 |

E2E는 개발 서버(5179)와 배포 빌드 미리보기(5180)를 함께 띄웁니다. 성능 테스트(게이트 5천 개에서 60fps)는 배포 빌드로, 기능 테스트가 끝난 뒤 따로 실행합니다.

### 구조

```
src/sim/     시뮬레이션 엔진 — 순수 TypeScript, React/DOM 의존 없음
             compile(칩 평탄화·버스 펼치기) → Engine(setInput → tick → read)
src/model/   저장 스키마, 칩 라이브러리, localStorage, 마이그레이션, 챌린지, 공유 링크
src/store/   editorStore(문서·선택·실행 취소), simStore(실행·속도·틱·파형 기록)
src/ui/      Header, Palette, Canvas(경로 찾기 포함), Inspector, Waveform, TruthTable, dialogs, challenges
src/theme/   tokens.css (색은 여기서만 정의)
tests/       fixtures(예제 회로), unit, e2e
```

엔진 테스트는 UI 없이 `compile → setInput → tick → read`만으로 작성합니다. 작업 규칙은 [`CLAUDE.md`](CLAUDE.md)를 참고하세요.
